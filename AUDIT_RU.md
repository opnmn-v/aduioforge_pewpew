# Аудит Ambient Forge 0.1.11

Дата: 25 октября 2026. Основа — приложенный `ambient-forge-review(2).zip`, а не текущая ветка GitHub. Исходный проект Marevo, MIT; лицензия и авторство сохранены. Это локальная review-сборка, без публикации или изменений чужого репозитория.

## Область проверки

Изучены `main.ts` (редактор, транспорт, громкость, публикация), `background.ts` (независимые плееры, асинхронная инициализация, seek, fade, pause/loop/cleanup), `model.ts` (схемы, URL и лимиты), `importer.ts` (Ambient Forge/Djinni), `storage.ts` (IndexedDB и fallback), Worker, manifest, CSP, конфигурация сборки и CI. Добавленные модули: `playback.ts`, `sync-access.ts`, `buffered-audio.ts`.

Библиотека сцен хранится **локально в браузере**, не в metadata комнаты. В комнате передаётся желаемое состояние воспроизведения; каждый участник самостоятельно загружает источники. Master — локальная настройка; scene/track volumes входят в общее состояние. Сцена по умолчанию — многодорожечный микс, папка — группа сцен.

## Новые функции

1. **Random scene** в папке: случайная сцена заменяет только сцены этой папки. Другие папки и их позиции сохраняются.
2. **Random track** на карточке: случайный незаглушённый трек вместо многодорожечного микса; выбор публикуется GM один раз и одинаков для клиентов. По возможности не повторять предыдущий выбор.
3. **Seamless loop**: короткие прямые аудиофайлы через AudioBufferSourceNode.loop, без сетевого/JavaScript-перезапуска на каждом круге. До 120 сек / 12 MiB; CORS необходим. Тишина в исходнике и плохой стык файла не исправляются автоматически.
4. Подсказки о своих аудиофайлах и требованиях к ссылкам; исправлен перенос элементов редактора, чтобы новая опция не обрезалась.

Не добавлены: загрузочный сервер, интеграция Drive/Dropbox OAuth, автоматическая очередь случайной музыки после конца трека, чтение удалённых YouTube-плейлистов.

## Проверки и сила доказательств

- **45 автоматических тестов, 7 файлов**: проходят; `npm run check` включает тесты и production-сборку.
- **Chromium с настоящими HTMLAudioElement**: A → B → stop A; B состоит из двух дорожек. Обе продолжают играть и двигаться по времени. Проверены master 59 / 30 / 10 / 1 / 0 / 80%, random track без немедленного повтора, random scene, pause/resume, редактор. Ошибок страницы нет.
- **Chromium с настоящим AudioContext**: секундный WAV проходит несколько циклов на одном looped AudioBufferSourceNode, без повторного создания источника; пауза/возобновление сохраняют управление. Это проверка механизма, а не субъективное прослушивание музыки.
- **YouTube — имитация API**: медленная готовность, duration=0 с последующим появлением metadata, late seek, A → B → stop A до готовности B, остановка до onReady, восстановление после onAutoplayBlocked, независимый fade и низкая громкость.
- Хранилище: пустой IndexedDB, переполненный localStorage, сериализация/commit, свежесть fallback, отказ обеих систем.
- Валидация и импорт, лимит broadcast, HTTP redirect и production security headers — автоматические проверки.

### Что нельзя объявить доказанным

Реальный YouTube внутри настоящей комнаты Owlbear в этой среде не проверен. Исходный симптом «после остановки A B молчит, но отмечен играющим» не удалось воспроизвести непосредственно с живыми YouTube iframe. Найдены и исправлены конкретные дефекты вокруг готовности, fade, seek и повторного запроса; их проверки проходят. Это не доказывает устранение всех возможных причин этого симптома в YouTube.

Численного нижнего ограничения в 60% в исходных формулах нет. Устранены известные причины потери команды и доработана работа с iframe; низкие значения проверены на настоящем аудиофайле. Субъективную громкость конкретных YouTube-роликов по этим тестам подтвердить нельзя.

## Остаточные ограничения

- **Фоновый iframe / таймеры:** HTMLAudio/YouTube fade управляется таймером, поэтому при жёстком throttling/freeze браузера может идти ступенчато или завершиться позже. Проигрывание буферного loop не требует этих таймеров. Полностью закрытая/выгруженная вкладка звука не воспроизводит.
- **YouTube:** блокировка встраивания, удалённый/регионально недоступный ролик, ограничения автозапуска, отсутствие metadata, загрузка видеоданных, реклама и нестабильный повтор не управляются полностью этим кодом. Не является audio-only транспортом.
- **Broadcast:** сохраняется предел около 16 KiB. Используется консервативный лимит 15 KiB; слишком большой микс отклоняется с сообщением. Chunking, постоянное серверное состояние и синхронизация по аудиосэмплам не реализованы.
- **Несколько GM:** проверки разрешают подключённых GM, но выделенного лидера/разрешения конкурирующих управляющих панелей нет. Практический режим — одна управляющая панель GM. При исчезновении всех источников текущего состояния позднему участнику негде восстановить проигрывание.
- **Доставка:** UI показывает ошибку отправки, но нет end-to-end ACK всех клиентов, повторной доставки при реконнекте и доказательства слышимости на аудиоустройстве.
- **Хранилище:** библиотека локальная, export/import необходим для другого браузера/домена. При полном отказе обоих хранилищ нужно сразу экспортировать резервную копию. Внутренний формат с меткой времени совместим с новым загрузчиком; откат на исходный код делать через Export/Import.
- **Буферные loops:** первоначальная полная загрузка и декодирование, дополнительная память на каждом клиенте. После декодирования проверяется длительность; это не потоковый проигрыватель длинных файлов. Нужны корректный CORS, формат браузера и подготовленный исходный стык.
- **Плеерный status:** отчёт может быть кратковременно Loading/Paused во время буферизации/seek; Playing не означает, что пользователь не выключил звук в системе или браузере.
- **Зависимости:** npm audit сообщает два moderate пункта: `uuid@9.0.1` и зависящий от него Owlbear SDK. Advisory касается v3/v5/v6 с переданным буфером; изученные файлы SDK используют v4 без буфера. API major override не применялся. Это ограниченная оценка достижимости, а не доказательство отсутствия любых уязвимостей SDK.

## Приёмка в комнате перед игрой

1. Подключить новую версию у GM и хотя бы одного игрока, старую выключить. Сохранить резервную библиотеку.
2. Взять два конкретных ролика YouTube, воспроизвести A → B → stop A и B → A → stop A. Повторить с fadeOut=0 и 3 секунды, а также пока B ещё грузится.
3. Проверить 100 → 59 → 30 → 10 → 1 → 0 → 30% и закрытие панели сразу после изменения.
4. Проверить длинный и короткий ролик, а также позднее подключение игрока спустя время длиннее короткого ролика.
5. Проверить отказ автозапуска и повторный Enable audio; убедиться, что статус меняется на Blocked/Source error, а не обещает Playing.
6. Проверить прямой WAV и Seamless loop на общедоступном CORS-хостинге, затем при закрытой панели. Отдельно прослушать исходный стык.
7. Проверить scene pause → global pause → global resume → scene resume; Everyone → Only me; быстрый restart и редактирование активного трека.

Если проблема остаётся только на YouTube, записать URL роликов, последовательность, fade in/out, статус и браузер; без этого нельзя отличить дефект приложения от поведения сервиса.
