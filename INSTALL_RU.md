# Ambient Forge 0.1.11 — как запустить исправленную сборку

В архиве есть исходники, тесты и готовая папка **dist**. Публичная версия автора по адресу ambient-forge.marevo.workers.dev от этого архива не обновляется.

## Подключение в Owlbear

1. В старом расширении нажать Export и сохранить свою библиотеку `.aforge`.
2. Разместить **содержимое папки dist** на HTTPS-хостинге в корне отдельного сайта. Подойдут Cloudflare Pages или Cloudflare Worker со статическими assets. На хостинге должны существовать `/manifest.json`, `/background.html`, `/assets/…`.
3. При использовании Workers: установить Wrangler, войти в свой Cloudflare, выбрать своё имя Worker в `wrangler.jsonc`, выполнить `npm ci`, `npm run build`, `npx wrangler deploy`. Чужой account_id из исходной конфигурации удалён. До реального деплоя URL вашей версии неизвестен.
4. В Owlbear добавить custom extension по адресу `https://ВАШ-ДОМЕН/manifest.json`.
5. Отключить прежний Ambient Forge в этой комнате: две версии с тем же каналом синхронизации не должны работать одновременно.
6. Открыть новую версию, импортировать свой `.aforge`, нажать Enable audio. Игрокам тоже нужно включить аудио и новую версию расширения.

**GitHub Pages с подпапкой репозитория:** текущая сборка использует абсолютные пути `/…`, поэтому её нельзя просто положить в `username.github.io/repository/`. Нужна отдельная настройка Vite base, HTML/CSS-путей и manifest. Для этого архива проще корневой HTTPS-сайт.

Библиотека хранится в браузере, отдельно для каждого origin. При переносе сайта нужен Export/Import. `.aforge` хранит ссылки и настройки, а не сами аудиофайлы. Внутренний формат сохранения получил метки времени; для возврата на старый код сначала экспортировать библиотеку, затем импортировать её в старую версию.

## Случайный запуск

- **Random scene** возле заголовка папки: выбрать одну сцену из этой папки, заменить только активные сцены этой же папки. Атмосфера из других папок продолжает звучать. При нескольких кандидатах немедленный повтор предыдущей сцены исключается.
- **Кнопка со скрещёнными стрелками на карточке**: выбрать один незаглушённый трек сцены. Все остальные дорожки этой сцены не запускаются. Повторное нажатие выберет другой трек, если доступно несколько.
- Обычный **Play** сохраняет исходную модель приложения: одновременно запустить все дорожки сцены.
- Это выбор одной композиции по нажатию. Автоматическая случайная очередь по завершении трека и импорт удалённого YouTube-плейлиста не добавлены. Ссылки YouTube должны указывать на отдельные видео, а не только на `list=…`.

## Короткий звук без паузы между повторами

В редакторе трека:

1. Указать прямую ссылку на свой аудиофайл. Для проверки стыка удобен WAV; OGG и MP3 также зависят от поддержки декодера браузера и подготовки файла.
2. Включить **Loop**.
3. Обе задержки **Delay** поставить в `0`.
4. Включить **Seamless loop** и сохранить сцену.

Этот режим полностью скачивает и декодирует файл один раз, затем повторяет его через AudioBufferSourceNode.loop в аудиодвижке браузера. Нет JavaScript-команды нового запуска на каждом обороте. Ограничения: до **120 секунд**, до **12 MiB** файла; сервер должен разрешать CORS. При ошибке ссылка/формат/CORS/размер отображается Source error. Автоматического отката на потенциально прерывистый loop нет — режим можно отключить вручную.

Если в самом файле записана тишина в начале/конце, она останется. Резкий перепад формы волны в точке стыка тоже останется: для чистого результата нужен подготовленный аудиолуп.

YouTube не поддерживает этот режим. Его повтор использует seek/play удалённого iframe-плеера и может содержать паузу. Для длинной музыки оставить обычный режим: он не требует полной загрузки в память до начала воспроизведения.

## Свои аудиофайлы и способы загрузки

Прямой загрузки с компьютера на сервер у приложения нет. В этой версии добавлен проигрыватель коротких лупов, а не файловый хостинг.

### Быстрее всего начать: Dropbox

1. Загрузить аудиофайл.
2. Дать доступ по ссылке без входа в аккаунт.
3. Скопировать ссылку в URL трека. Приложение автоматически заменит `dl=…` на `raw=1` и сохранит `rlkey`.

Для обычного проигрывания достаточно доступного аудиоответа. Для Seamless loop отдельно требуется разрешённый CORS: не каждая ссылка/конфигурация облачного хранилища его обеспечивает. Работоспособность конкретной ссылки нужно проверить в расширении.

[Документация Dropbox](https://help.dropbox.com/share/force-download).

### Удобнее для постоянного использования: своё хранилище с прямыми ссылками

Для собственного небольшого инструмента я бы выбрал Cloudflare R2 со стабильным адресом чтения и CORS. R2 — хранилище, а не готовая кнопка загрузки в этом приложении. Сначала можно загружать файлы через панель Cloudflare и вставлять адреса.

Дальнейшая доработка: drag & drop в расширении → сервер выдаёт короткоживущий presigned PUT URL → браузер загружает файл → расширение добавляет стабильную ссылку чтения в библиотеку. Секретные ключи должны оставаться на сервере. Временный подписанный URL загрузки нельзя сохранять в качестве постоянного адреса трека.

[Загрузка в R2](https://developers.cloudflare.com/r2/objects/upload-objects/), [CORS](https://developers.cloudflare.com/r2/buckets/cors/).

### Google Drive

Обычная `drive.google.com/file/d/…/view` — страница просмотра, а не аудиоресурс. В этой версии нет интеграции Google Drive API и авторизации. Универсальная замена URL не даёт гарантии потокового воспроизведения или CORS для буферного режима.

Технически можно сделать отдельный импорт через Drive API или перенос на хостинг: Google документирует получение содержимого через `files.get?alt=media` и браузерные download-ссылки `webContentLink`. Но это отдельная интеграция, а не уже работающая функция этого архива.

[Документация Google Drive](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

### Трафик YouTube

Текущий код использует YT.Player, то есть видеоплеер. Картинка вынесена за экран; это не режим audio-only и не гарантия отсутствия загрузки видеоданных. Конкретный объём трафика зависит от поведения YouTube. У каждого участника комнаты свой плеер и своя загрузка; ведущий не ретранслирует звук остальным. Прямой аудиофайл убирает видеотрафик.

## Проверка разработчиком

Node.js 22.12+:

```bash
npm ci
npm run check
```

Браузерная проверка с настоящими HTMLAudioElement и Web Audio и имитацией только Owlbear SDK:

```bash
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

Скрипт сам запускает отдельный Vite с тестовым SDK, создаёт короткий синусоидальный WAV в памяти, проверяет управление и останавливает сервер. Тестовый SDK подключается только специальным `tests/browser/vite.config.ts`; production-сборка использует настоящий Owlbear SDK. Можно задать `CHROMIUM_PATH` для уже установленного Chromium и `BROWSER_TEST_ARTIFACT_DIR` для временных снимков интерфейса.

Тесты YouTube используют имитацию API. Реальная проверка YouTube внутри комнаты Owlbear остаётся обязательной перед повседневной игрой; см. `AUDIT_RU.md`.
